# متجر 3MH التقني — 3MH STORE

سوق رقمي متكامل للمنتجات التقنية من تطوير **3MH TECHNOLOGIES**:
سكربتات وأكواد برمجية، أدوات أتمتة، كورسات تقنية، واشتراكات وتراخيص رقمية —
مع سلة مشتريات، بوابة دفع، تتبع طلب، فاتورة رقمية قابلة للطباعة، ولوحة تحكم مشرف.

- **الواجهة:** React 18 + Vite + TypeScript + Tailwind CSS + Lucide (RTL عربي كامل، خط Cairo/Tajawal)
- **قاعدة البيانات:** ملفات JSON على مستودع GitHub خاص عبر GitHub REST API (`@octokit/rest`)
- **الاستضافة المستهدفة:** Hugging Face Spaces (Docker / Node.js) — أو أي استضافة SPA

---

## 1. المتطلبات

- Node.js 20+
- مستودع GitHub **خاص** يُستخدم كقاعدة بيانات (يحتوي على `data/products.json` و `data/orders.json`)
- توكن GitHub بصلاحيات **Contents: Read & Write** على ذلك المستودع فقط (fine-grained token)

## 2. الإعداد المحلي

```bash
cp .env.example .env
# املأ القيم داخل .env
npm install
npm run dev
```

المتغيرات المطلوبة:

| المتغير | الوصف |
| --- | --- |
| `VITE_GITHUB_OWNER` | اسم المستخدم أو المنظمة المالكة لمستودع البيانات |
| `VITE_GITHUB_REPO` | اسم مستودع قاعدة البيانات (خاص) |
| `VITE_GITHUB_BRANCH` | الفرع المستخدم (افتراضي `main`) |
| `VITE_GITHUB_TOKEN` | توكن GitHub للقراءة والكتابة |
| `VITE_ADMIN_PIN` | رقم دخول لوحة التحكم `/admin` (افتراضي `1379`) |
| `VITE_ASSET_SECRET` | مفتاح تشفير روابط تسليم الأصول — يجب أن يطابق المفتاح المستخدم عند توليد `products.json` |

> **ملاحظة:** عند غياب متغيرات GitHub يعمل المتجر بوضع العرض المحلي (قراءة فقط من
> `data/products.json` المضمّنة في البناء)، أما إنشاء الطلبات وإدارة لوحة التحكم
> فتتطلب ضبط المتغيرات.

## 3. بيانات المتجر (data/)

- **`data/products.json`** — كتالوج المنتجات. روابط الأصول (`access`) مشفرة AES-GCM بمفتاح
  مشتق من `VITE_ASSET_SECRET` ولا تُفك شيفرتها إلا داخل الفاتورة بعد التحقق من الطلب.
- **`data/orders.json`** — سجل الطلبات (يُدار تلقائياً عبر المتجر ولوحة التحكم).

### إعادة توليد تشفير الأصول بعد تعديل المنتجات

اكتب المنتج الجديد مع حقل `access` بالصيغة النصية ثم شغّل:

```bash
npm run seed:assets
```

## 4. النشر على Hugging Face Spaces

المتجر مُصمم للنشر على Hugging Face Spaces كحاوية Docker تعمل بخادم Node
خفيّ (`scripts/server.mjs`) يقدّم البناء الثابت ويولّد `/config.json` من
متغيرات البيئة **وقت التشغيل** — فلا تُضمَّن المفاتيح في حزمة JavaScript.

1. أنشئ Space من نوع **Docker** (أو غيّر نوع الـ Space الحالي من Static إلى Docker).
2. ارفع الملفات إلى الـ Space (سيرفر Dockerfile جاهز في جذر المشروع).
3. أضف الأسرار في **Settings → Variables and secrets**:

| المتغير | الوصف |
| --- | --- |
| `GITHUB_OWNER` | مالك مستودع قاعدة البيانات |
| `GITHUB_REPO` | اسم مستودع قاعدة البيانات |
| `GITHUB_BRANCH` | الفرع (افتراضي `main`) |
| `GITHUB_TOKEN` | توكن GitHub (Contents: Read & Write) |
| `ADMIN_PIN` | رقم PIN للوحة التحكم `/admin` |
| `ASSET_SECRET` | مفتاح تشفير روابط الأصول — يُطابق المفتاح المستخدم في `products.json` |

> **تحذير أمني:** توكن GitHub يُمرَّر للواجهة لقراءة/كتابة قاعدة البيانات — وهو
> حاجز عملي لأن تشفير الأصول يمنع فتح روابط التسليم قبل التحقق، لكن يفضَّل
> استخدام fine-grained token بصلاحية هذا المستودع فقط، وإعادة توليد الأصول
> المشفرة في حال تسريب المفتاح.

## 5. مسارات التطبيق

| المسار | الوظيفة |
| --- | --- |
| `/` | الرئيسية: Hero، البحث الفوري، فلاتر الأقسام، شبكة المنتجات، نافذة تفاصيل المنتج |
| `/checkout` | إتمام الطلب: بيانات العميل ← اختيار الدفع (USDT/BTC/ETH + QR) ← إرسال إثبات العملية |
| `/track/:id` | تتبع الطلب العام: حالة العملية، وبعد التحقق تظهر روابط الأصول |
| `/invoice/:id` | الفاتورة الرقمية القابلة للطباعة (PDF) — تفتح الروابط تلقائياً عند التحقق |
| `/admin` | لوحة التحكم: إحصاءات، قائمة الطلبات، اعتماد/رفض الدفع (يُكتب في `orders.json`) |

## 6. سير عمل الطلب

1. العميل يضيف منتجات للسلة ويتابع إلى `/checkout`.
2. يختار طريقة الدفع، ينسخ العنوان، ويرسل **معرف العملية (TxID)** أو مرفق الإثبات.
3. يُنشأ الطلب بحالة `pending` في `data/orders.json` داخل المستودع.
4. المشرف من `/admin` يراجع الإثبات وينقر **اعتماد الدفع** → الحالة `verified`.
5. فاتورة العميل تكشف فوراً روابط الأصول المشفرة + شارة التحقق.
